# Strategy — the four content pillars

Which channels to launch, in what order, and why. Built on the Monstah principle:
**ONE WORLD ENGINE → four editorial policies** (a channel is a policy over the shared
engine, not a separate infrastructure).

## 1. PREHISTORIC EARTH — the ideal automation niche
Viewers cannot demand authentic footage — everything is reconstruction already. That's
the perfect fit for an evidence-driven engine:

```
PBDB + geology + papers + museum images + canonical reconstruction assets
        ↓
episode engine → LTX
```

Four identities from ONE engine:
| Identity | Premise | Editorial policy |
|----------|---------|------------------|
| **TITANS OF DEEP TIME** | prehistoric terrestrial worlds | ecosystem reconstruction, long-form |
| **ANCIENT OCEANS** | marine prehistory | seaway/paleocean reconstruction |
| **EXTINCTION** | mass extinction / ecosystem collapse | before → event → after → survivors |
| **PREHISTORIC MATCHUPS** | battle simulations | Shorts + Monte Carlo outcome |

Already built in monstah: `prehistoric` + `ancient-oceans` channels; the d20 battle
engine + Monte Carlo power Matchups; Extinction is a new editorial policy over the same
PBDB + Macrostrat substrate.

## 2. DEEP OCEAN — the best niche on YouTube right now
Direct signal: **YouTube itself** flagged the Schmidt Ocean Institute deep-sea
livestreams as a significant trend (viewers watch dives for hours, reacting to unknown
organisms). That's both **scientific-discovery** content and educational **slow TV**.

Ridiculous thumbnail/title machinery:
```
The Animal Found 8,000 Metres Down
Nothing Should Be Living Here
What Actually Hunts a Giant Squid?
The Deepest Predator Ever Recorded
The Ecosystem Beneath the Antarctic Ice
```

Input data is excellent: **OBIS, GBIF, GloBI, WoRMS, papers, oceanographic datasets.**
Built in monstah: `deep-blue` channel (OBIS-driven). This is one of the first to launch.

## 3. AI HISTORICAL RECONSTRUCTION — the breakout
AI "time traveller"/historical-vlogger formats are reaching millions of views
(AI Tudor London, Ancient Rome...). But current implementations have a weakness:
*cool AI video + questionable accuracy.*

We can build the stronger version:
```
historical evidence graph + maps + archaeology + primary sources
  + scholarship + canonical reconstruction + AI cinematography
```
Potential channels:
| Channel | Episode example |
|---------|-----------------|
| **THE PAST ALIVE** | "What London actually looked like in 1666" |
| **LOST CITIES** | "What Tenochtitlan looked like before Cortés" |
| **ONE DAY IN...** | "One day in Alexandria, 250 BCE" |
| **ANCIENT ENGINEERING** | "How Rome actually supplied a million people" |

The moat isn't generating Romans — everyone will. The moat is knowing *which street,
which buildings, which clothes, which foods, which population, which language, which
season, which technologies* — and **being able to prove it**. That is Monstah's
architecture applied to history.

## 4. EXOPLANETS / ALIEN WORLDS — the epistemic fit
The most natural extension:
```
NASA Exoplanet Archive + stellar catalogs + atmosphere models
  + habitability models + planetary science papers
        ↓
WorldSnapshot → visual reconstruction
```
Titles write themselves:
```
The Planet Where It Rains Glass
What Would You See on TRAPPIST-1e?
A Year on a Tidally Locked Earth
What the Sky Looks Like on Kepler-186f
```
The epistemic tri-layer **OBSERVED / MODELLED / SPECULATIVE** (our `core/truth` firewall)
is almost freakishly well suited to exoplanets — the whole object is a constrained model.

---

## Priority / build order
1. **Prehistoric Earth** (Titans + Ancient Oceans + Matchups) — most automation-friendly.
2. **Deep Ocean** (`deep-blue`) — best current niche, data-rich, high throughput.
3. **Historical reconstruction** — breakout genre, needs an archaeology/primary-source adapter.
4. **Exoplanets** — natural fit, needs the NASA Exoplanet Archive TAP adapter.

The principle everywhere: **one engine, many editorial policies.** Do not build five
infrastructures; build one engine and parameterize it (see `docs/CHANNELS.md`,
`docs/THESIS.md`).
